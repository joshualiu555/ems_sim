# Emergency Medical Services Simulator

A real-time EMS dispatch simulator written in C++20. It models 911 calls flowing into a city grid, dispatches the nearest available ambulance to each scene, transports patients to the nearest hospital, and visualizes the whole process live on an interactive dashboard.

The project is split into three components:
1. A dispatch server
2. Call clients that feed it emergencies
3. UI dashboard 

They are wired together over TCP with JSON messages and PostgreSQL.

## Features

- **Event-driven simulation** - Driven by event and call priority queues
- **Procedural city maps** — A grid of road and building cells with shortest-path routing between them generated by graph algorithms
- **Dispatch logic** — Finds available ambulances, routes the closest one to a call, then to the nearest hospital with available capacity.
- **Call priorities** (Alpha → Echo) and **Ambulance types** (ALS / BLS) - Each with its own behavior and TTL before a call expires.
- **Live dashboard** - Dear ImGui showing the grid, ambulance movement, call flashes on expiry, patient discharges, and a legend.
- **Multiple simulations** - Plus play / pause / speed + save / replay controls.
- **Analytics** - Percentage of patients saved, average call time, etc. 
- **Custom map input** - Place ambulances and hospitals, then randomly generate roads

## Architecture

```
┌──────────────┐   TCP/JSON   ┌─────────────────────┐   libpqxx   ┌────────────┐
│  call_client │ ───────────► │   dispatch_server   │ ──────────► │ PostgreSQL │
│ (emergencies)│              │  (simulation engine)│             │            │
└──────────────┘              └─────────────────────┘             └────────────┘
                                        ▲
                              TCP/JSON  │
                              ┌─────────┴────────┐
                              │        ui        │
                              │ (ImGui dashboard)│
                              └──────────────────┘
```

| Component | Path | Role |
|-----------|------|------|
| `dispatch_server` | [src/apps/dispatch_server](src/apps/dispatch_server) | Hosts the simulation engine, accepts TCP clients (asio), ticks all simulations, persists state to Postgres. |
| `call_client` | [src/apps/call_client](src/apps/call_client) | Generates emergency calls and submits them to the server. |
| `ui` | [src/apps/ui](src/apps/ui) | Dear ImGui dashboard; on Windows it can launch the server process itself. |
| Engine | [src/engine/logic](src/engine/logic) | Simulation, SimulationHandler, dispatch, map / pathfinding, and event handling |
| Shared models | [src/shared/models](src/shared/models) | Call, Ambulance, Hospital, Event, Map, Node, Dispatch. |
| Networking | [src/networking](src/networking) | asio TCP Server / Session. |
| DB | [src/engine/db](src/engine/db) | Postgres wrapper (libpqxx) |
| Migrations | [db/migrations](db/migrations) | Schema edits |

## Tech stack

- **Language:** C++20
- **Build:** CMake (≥ 3.15)
- **Networking:** [asio](https://github.com/chriskohlhoff/asio) (standalone) TCP, JSON [nlohmann/json](https://github.com/nlohmann/json)
- **Database:** PostgreSQL [libpqxx](https://github.com/jtv/libpqxx)
- **UI:** [Dear ImGui](https://github.com/ocornut/imgui) + [GLFW](https://github.com/glfw/glfw) + OpenGL 3
- **Testing:** [GoogleTest](https://github.com/google/googletest) via CTest

All third-party dependencies are fetched automatically at configure time with CMake `FetchContent` — see [dep/CMakeLists.txt](dep/CMakeLists.txt). No manual install of these is required.

## Prerequisites

- A C++20 compiler (Clang, GCC, or MSVC)
- CMake ≥ 3.15
- Local PostgreSQL
- GUI system libraries - Look in `src/apps/ui/CMakeLists.txt` for specifics to OS

## Setup

### 1. Configure the database 

```bash
export POSTGRES_DB_CONNECTION_URL="postgresql://USER:PASSWORD@localhost:5432/ems_sim"
```

Migrations in [db/migrations](db/migrations) are applied automatically when the server starts.

### 2. Build

```bash
cmake -S . -B build
cmake --build build
```

### 3. Run

Start the simulation server

```bash
./build/src/apps/dispatch_server/dispatch_server
```

Start the dashboard

```bash
./build/src/apps/ui/ui
```

Start a call client (should be done through UI)

```bash
./build/src/apps/call_client/call_client
```

The server listens on port `8080` and clients connect to `127.0.0.1:8080`.

## Testing

ctest --test-dir build --output-on-failure

## How the simulation works

1. A `call_client` generates a `Call` and sends it to the server.
2. The engine enqueues a `CallReceived` event. On each tick, `SimulationHandler::tick_all_simulations()` advances every active simulation.
3. Dispatch selects the closest available ambulance and the nearest hospital with capacity.
4. The ambulance moves cell by cell along its path, generating `AmbulanceArriveAtScene`, `TransportStart`, `AmbulanceArriveAtHospital`, `PatientDischarged`, and `AmbulanceBackAtStation` events. Transport extends a patient's TTL and reaching a hospital saves them.
5. Calls that aren't reached in time emit `CallExpired`.
